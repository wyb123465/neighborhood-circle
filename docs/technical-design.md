## 已实现的样例算法

路网为 13 × 11 节点、间距 160 米的无向图。滨河样例仅允许两处横向过河边，连通样例保留所有相邻边。设施相同，路网差异可独立验证。合成位图底图从同一图生成，Leaflet 使用 `CRS.Simple`，坐标不得混入真实经纬度。

NetworkX Dijkstra 计算各点最短路径。每类设施取最近路网距离，除以恒定步速；以阈值判断可达。空类别按无设施输出，不生成虚构距离。片区采样节点等权计数，既不代表人口，也不代表服务面积。

候选设施逐点枚举，对覆盖最少类别计算边际新增可达节点，排序输出前三个。单个候选点加入后重新计算所有所选类别的覆盖交集。不同候选是互斥方案，不累加增益；未核验土地、容量、预算。

中心点可达点集使用同一图，但不等于“居民获得服务的覆盖率”。图上色块只是采样点周边的视觉标记，不是连续精确等时圈。1 公里专项检查使用原有菜市场/药店/小学的欧氏距离，独立于时间阈值与模拟设施。

数据与算法版本、类别、步速、阈值、中心、候选点参与证据哈希。相同输入输出相同结果。输出不含没有校准依据的置信度或随机指标。缓存仅加速本地样例图的距离矩阵与底图位图，不是百度 API 缓存或接口性能验证。

## 接口

- `GET /api/health`：合成数据、大模型/百度未连接状态。
- `GET /api/communities`：两个人工样例。
- `GET /api/communities/{id}/inspection`：支持 `category=医疗,养老`、`minutes`、`speed`、`center`、`addition_node` 与 `addition_category`。
- `GET /api/communities/{id}/map.png`：由合成图渲染的位图，不使用外部地图瓦片。
- `POST /api/agent/inspect`：仅关键词识别，不是智能体或外部工具调用；未识别时返回 400，不假称执行。
- `POST /api/report`：重新计算后导出 Markdown，参数口径与结果一致。

所有路由按白名单公开，禁止挂载仓库根目录。日志与凭证不放入静态目录。没有外部接口时不伪造“调用成功”或回放状态。

## 真实模式设计：接口适配器与演示闭环已实现

当前已实现服务端百度地图适配器和部分真实链路：

- 服务端 AK 配置、超时、短期缓存、并发限制和错误归一化。
- 地理编码、地点检索 V3/V2 兼容、步行路线三个适配器。
- 批量算路 RouteMatrix 按路线对数拆块；失败时回退逐设施路线，并保留失败状态。
- `/api/live/inspect` 完成地址定位、四类 POI query、UID 去重、中心到设施路线证据、1 公里菜市场/药店/小学专项检查。
- 1 公里专项检查按 250 米等权网格输出 `complete` / `unknown`，对已知缺口按类别生成最多 3 个贪心覆盖参考点。
- `/api/live/isochrone` 用批量步行测时构造网格采样近似等时圈，并对边界锚点做预算内加密。
- `/live.html` 将等时圈、设施路线、盲区、规划参考点和方法警告放在同一条可追溯报告链路中。
- 实时结果显式标记为 `live-partial`，不会把中心到设施比例写成居民覆盖率。

仍需补证或明确不做的部分：

1. 服务端 AK 不向前端下发；部署方仍需确认域名/IP 限制、服务开通、配额和数据使用条款。当前已强制 IPv4，出口变化仍可能导致白名单失败。
2. 统一 BD-09 等输入输出口径，禁止把 WGS84/米制样例混入百度接口。百度返回时长与合成算法固定步速必须分开表述。
3. 服务覆盖仍需从居住/网格起点计算到各类设施的最短可达性，不能用中心等时圈比例当居民覆盖率。
4. 不拟合连续边界、不假设可达区域为星形；网格采样保留障碍孔洞与未知点，但仍需用更多人工样本估计误分类风险。
5. POI 子类、营业状态、设施容量、土地适宜性、建设成本和人口权重不由当前接口自动推断；规划参考点不等于建设方案。
6. 真实结果需注明数据时点、返回状态、已评估/未知样本比例；AI 仅基于工具结果生成可引用解释，当前默认保持 rule-only。
