# 邻里圈 v0.6 视觉与体验升级方案

日期：2026-10-14。状态：P0界面、情景比较和打印摘要已实施，并补充本机历史及核验备注；验收见[记录](acceptance-v0.6.md)。真实道路底图仍依赖网页端配置。v0.5提交包保留为历史基线。

## 1. 参考与设计取舍

已查看当前邻里圈工作台，并实际访问、查看以下官网首页画面：

| 参考 | 实际观察 | 用到邻里圈 |
| --- | --- | --- |
| [Apple中国官网](https://www.apple.com.cn/) | 薄导航、强标题层级、整幅产品主视觉、少量主次按钮，分屏突出一个主题 | 项目首页突出一句定位和真实产品主视觉；关键数字、按钮、留白有层级 |
| [比赛官网](https://www.oschina.net/os2026/) | 圆角悬浮导航、左侧主题文字与右侧视觉、清楚的栏目导航、浅底上的鲜明主题区 | 简洁悬浮导航、清晰的展示章节、以自己的路网图形成品牌记忆 |

参考的是信息组织、比例和交互。保留邻里圈现有绿色品牌，不复制Apple产品图、标志、字体资源或比赛官网的视觉素材。

建议方向：浅白/浅灰背景、深墨色文字、森林绿主色，地图与路网作为主要视觉。展示首页允许更舒展；分析工作台保持适合做判断的信息密度。

## 2. 当前界面的具体问题

1. 执行过程排在结论前，已完成的6条模型/工具步骤仍占据显著空间，结果入口后移。
2. 结论是多段等权文字，设施数量、缺口、未知和下一步没有明显主次；用户需要自己提炼。
3. 地图位于长结论下方，难以同时看判断和位置；在桌面端未充分利用横向空间。
4. 每条事实都重复完整来源与16位证据编号，长绿色按钮抢占内容注意力。
5. 首页、真实页、智能助手分为三个工作入口，数据模式和操作路径需要用户自行理解。
6. 局部米制点图有分析价值，但缺少道路/地名参照；地图的缩放、图层选择和点位详情入口较弱。

## 3. 页面结构

### 项目展示首页

- 主标题建议：**走得到，才算生活圈。**
- 说明：从设施缺口到规划参考，每一步都有地图证据。
- 主按钮“开始体检”，次按钮“体验合成样例”。
- 主视觉用自己的合成路网、桥梁绕行和候选点，图形与计算结果对应，显示合成来源。
- 后续章节：直线与路网差异 → 一个方案的重算前后 → 真实地图与未知边界 → 开源复现及材料。
- 案例数字使用已验证结果；不新增未经校准的健康评分、人口指标或建设收益。

### 分析工作台

桌面端为“左侧需求与参数 / 中部地图 / 右侧诊断与方案”，顶部提供简短结果摘要。窗口变窄时先压缩参数栏，最后转为“结论 / 地图 / 方案”页签与可打开的参数面板。

- 结果区首先回答：查了什么、发现什么缺口、哪些仍未知、下一步核验什么。
- 关键指标依模式变化：合成展示等权覆盖与缺口；真实展示已评估设施、专项已知缺口与待核验样点。每个数字旁保留分母和口径。
- 执行中展示实际步骤和停止按钮；完成后收为一行摘要，详情可展开，失败步骤仍能直接看到。
- 来源在结果顶栏显示；事实使用短引用编号，点击可定位地图并查看完整证据信息。
- 操作保留一个明确主按钮，其他操作放在对应区块；避免整排按钮与内容竞争。
- 移动端保持发送、停止、结果与地图切换可达，不要求用户横向拖整页。

## 4. 视觉与交互规范

- 沿用现有CSS变量与原生HTML/CSS/JS，不因外观升级更换前端框架。
- 深色主文字与浅色次级文字拉开对比；正文约15–16px，辅助文字保持可读，关键数字使用等宽数字。
- 展示首页标题比工作台更大；工作台优先让地图、结果和设施详情清楚。
- 少量白色浮层、柔和阴影和不同层级圆角；线条只用于必要分组。
- 绿色用于主操作和重点数据，红/黄只表达明确的阈值、未知和待复核状态。
- 图层切换、点位定位和面板展开使用短CSS过渡；尊重减少动画设置，不人为拖慢真实进度。
- 导航、图标、表单、弹层和导出入口在三个已有页面保持一致，旧入口继续可访问。

## 5. 值得增加的功能

| 优先级 | 功能 | 新增价值 | 实施约束 |
| --- | --- | --- | --- |
| P0 | 地图图层与设施详情联动 | 切换设施、缺口、未知、近阈值点；点设施查看类别、耗时和证据；一键到官方地图核对 | 复用已有分析结果；路线未知单列；官方核对链接不把服务端AK交给浏览器 |
| P0 | 10/15/20分钟情景对比 | 用并排图表看到阈值变化对同一片区的影响，适合比赛演示 | 固定同一组样点、范围和设施，统一分母；真实模式复用原始测时，不随意改写百度耗时 |
| P0 | 一页可打印报告 | 图、结论、候选与证据在一页呈现，方便评委和社区使用 | 保留来源、时点、参数与未知；现有Markdown/JSON继续保留 |
| P1 | 本地体检项目与历史记录 | 保存地点、参数、快照和方案，回到上次结果，不依赖登录 | 明确仅存本机，过期数据有日期提示，不保存凭证；不同数据版本分开标注 |
| P1 | 核验清单与备注 | 将近阈值路线、POI分类和出入口问题变成可处理事项 | 原始证据不改写；备注、来源、核验时间独立保存，不将用户标记冒充实测真值 |
| P1 | 真实道路底图 | 让用户看懂样点位于哪条街道，提升空间可读性 | 需单独配置网页端地图能力；网络或配置不可用时保留离线示意图 |

候选重算与依据追问已经实现，本轮是在地图交互、比较方式、项目记录和报告呈现上增强，不把已有功能重新包装为新增。

真实底图技术选型以 [百度JSAPI 4.0开发准备](https://lbs.baidu.com/docs/jsapi?title=jsapi4/quickstart/prepare) 为依据：使用浏览器端AK及站点Referer限制，与当前服务端IP白名单AK区分。新项目不采用已标为历史版本的JSAPI GL。优先交付官方地图核对入口，再视配置完成底图嵌入。

## 6. 实施顺序与验收

1. 先重排工作台：结论、地图、参数与过程层级；不修改计算口径。
2. 补统一项目首页、字体、颜色、图标、空状态和窄屏布局。
3. 加地图详情/图层、固定样点情景对比与一页报告。
4. 时间允许再加本地历史与核验备注；真实底图取决于网页端配置。
5. 重新检查键盘操作、停止/重试、旧结果失效、图层证据定位与来源标签；复测关键AI案例。
6. 新界面验收后再同步演示视频、PDF和源码包；原v0.5提交包保留可回溯。

验收目标：桌面首个工作区能同时看到主要结论和地图；窄屏不横向溢出；“发现缺口→看证据→比较→导出”的路径连贯；没有API配置时仍可完整演示合成路径。

本轮不扩展全市平台、人口预测、建设收益、3D漫游或通用聊天。优先让已有真实分析能力更容易理解和使用。
