# POI 归一化与多来源核验策略

## 当前实现

百度 POI 是设施与路线输入源。`live_inspection.py` 按 UID 去重，缺 UID 时使用名称和坐标组合身份；合并检索词与类别命中，保留子类是否可参与覆盖的字段。培训、托管、游泳馆等明显非普通小学结果不计入小学专项。分页截断、查询失败或检索范围不足时保留 unknown，不据此证明现实中没有设施。

政府公开资料是独立的类别/文字地址核验来源，现有核对见 `poi-crosscheck-2026-10-13.md`。它们没有被假装成第二份完整地图 POI 库，也没有自动替换百度坐标或路线结果。

## 跨来源冲突处理

| 字段 | 策略 | 当前阶段 |
| --- | --- | --- |
| 名称、类别 | 保留原始名称及来源；普通小学等资格优先参考主管部门资料，不能只按名称关键词确认。 | 排除规则已实现；权威资料由核验记录关联。 |
| 地址、同名设施 | 名称/文字地址支持关联；同名不同址分别保留。自动近邻候选仅提示核验，不直接合并为同一入口。 | UID去重已实现；跨来源近邻匹配待实现。 |
| 坐标与入口 | 百度返回BD-09用于计算；不同来源坐标需显式转换、记录原来源。主管部门地址不自动推成精确入口坐标。 | 官方坐标转换已实现；入口需独立核验。 |
| 营业/开放状态 | 记录核验日期与独立来源；旧名录不自动视为当前营业。 | 尚需团队补证。 |
| 分歧 | 原始API结果保留，本机核验意见单列；排除意见必须说明来源，不改写历史响应。 | 核验备注已实现。 |

## 评价方式

固定样区、时点、检索词与分页范围，独立选取三类设施及算法判断的缺口点。分别统计类别误命中、漏检、入口差异和未知；样本不是随机抽样时明确说明，不能用少量正例估计全量召回率。原始响应和联系方式不进入公开仓库。
