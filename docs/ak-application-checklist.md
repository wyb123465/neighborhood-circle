# 百度地图 AK 自助申请清单

目标：拿到一个**服务端** AK，跑通邻里圈的真实链路。
适用：走个人认证（即时生效、免费）。企业认证配额高两个数量级，但需营业执照且要 3-5 个工作日。
事实来源：百度地图开放平台官方 FAQ「开发者认证」「配额提升」，查证于 2026-09-10。

---

## 第 0 步：先读这条，别踩

> **每个百度账号（passport ID）只有 5 次开发者认证机会。5 次都没通过，该账号永久无法再申请认证。**

个人认证被驳回的原因几乎只有两个：**身份证照片不清晰**、**填写信息与身份证不一致**。提交前请逐项自检：

- [ ] 身份证正反面照片清晰、完整、无遮挡、无反光、四角都在画面内
- [ ] 姓名、身份证号与证件**逐字一致**（注意生僻字、姓名中是否有空格）
- [ ] 手机号、邮箱为本人可用且能收短信/邮件
- [ ] 「使用场景」填写具体，不要写「测试」「学习」这类模糊内容（建议写：面向社区治理的开源工具「15 分钟生活圈」可达性分析，参赛作品，非商用）
- [ ] 个人认证**仅支持中国大陆地区用户**
- [ ] 同一项目/组织不要用多个账号重复申请认证（官方明确会封禁）

---

## 第 1 步：注册并登录

1. 打开 <https://lbs.baidu.com/apiconsole/key>（控制台）
2. 没有百度账号就先注册，再登录

## 第 2 步：开发者认证（即时生效）

1. 控制台左侧边栏 →【个人中心】→【开发者认证】
2. 选择**个人开发者** → 点【立即认证】
3. 填写：姓名、手机号、邮箱、工作地址、身份证正反面照片、使用场景
4. 勾选《百度地图开放平台开发者认证协议》→ 提交
5. **个人认证即时返回结果**，通过后会收到短信/邮件通知

> 注意：网上有文章说「1-3 个工作日」，那是百度智能云（cloud.baidu.com）的规则，与百度地图开放平台不是同一个平台。以开放平台官方 FAQ 为准：个人认证即时返回。
> 如果认证没通过，别急着重复提交——先看拒绝原因，改完再交，你只剩 4 次机会。

## 第 3 步：创建应用并拿 AK

1. 控制台左侧边栏 →【应用管理】→【我的应用】→【创建应用】
2. **应用类型必须选「服务端」**
   - 选错成「浏览器端」会导致 Web 服务 API 全部调不通，这是最常见的坑
   - （浏览器端 AK 是给 JavaScript API 用的，本工作区另一个百度地图赛题才需要）
3. 应用名称填有辨识度的，例如 `邻里圈-15分钟生活圈`
4. **「启用服务」必须勾上这几个**，漏勾会在调用时返回无权限：

   | 服务 | 用途 | 本项目对应的调用 |
   | --- | --- | --- |
   | 地理编码 | 地址转坐标 | `/geocoding/v3/` |
   | 地点检索 | POI 搜索 | `/place/v3/around` |
   | 步行路线规划 | 中心点到设施的距离与耗时 | `/direction/v2/walking` |

   建议保持默认全勾，只多不少。

5. **安全策略填 IP 白名单**
   - 服务端 AK 用 **IP 白名单**（不是 referer 白名单，referer 是浏览器端用的）
   - 本地开发填你的公网出口 IP；查公网 IP 可在浏览器搜索「我的IP」
   - 如果只在本机跑，也可以先留空以便调试，**但拿到可用结果后务必补上**
6. 提交 → 得到 32 位 AK

## 第 4 步：填入项目配置

在项目目录（`邻里圈：15 分钟生活圈智能体检与规划助手`）执行：

```powershell
Copy-Item .env.example .env
```

然后编辑 `.env`，只改这一行：

```
BAIDU_MAP_AK=你的32位AK
```

**建议同时改这一行**（个人认证地点检索只有 100 次/日，full 画像一次体检就吃掉 10 次）：

```
BAIDU_POI_QUERY_PROFILE=narrow
```

其余保持默认。`BAIDU_API_MAX_CONCURRENCY` 默认已是 3，与个人认证的 3 次/秒对齐，**不要调高**。

> `.env` 已在 `.gitignore` 中，且代码不会把 AK 写进日志、响应或报告。仍然请勿截图 AK 或粘贴到聊天里。

## 第 5 步：一行命令验收

```powershell
.\.venv\Scripts\python.exe scripts\check_live.py --address "上海市长宁区愚园路" --city 上海市
```

脚本只消耗约 **8 次调用**（1 次地理编码 + 4 次地点检索 + 3 次步行路线），并在 `.runtime\` 下生成 Markdown 验收报告。看到报告即表示真实链路通了。

同时可在浏览器打开 <http://127.0.0.1:8000/api/live/status>，确认 `configured` 为 `true`。

## 常见错误对照

| 现象 | 原因 |
| --- | --- |
| `/api/live/status` 仍显示 `configured: false` | `.env` 没生效（确认文件名是 `.env` 不是 `.env.txt`），或没重启服务 |
| 返回 `无权限` / status 非 0 | 创建应用时漏勾了对应服务；或应用类型选成了浏览器端 |
| HTTP 403 | IP 白名单没加当前出口 IP |
| 触发限流 | 并发或频率超过账号配额（个人认证 3 次/秒、地点检索 100 次/日） |
| 地址解析不到坐标 | 地址写得太模糊，补上城市和道路名 |
| `APP IP校验失败`，但白名单里明明填了出口 IP | 后端走了 **IPv6** 出口：`api.map.baidu.com` 有 AAAA 记录，家宽（尤其移动）会优先 v6，百度看到的是临时 IPv6 地址而非白名单里的 IPv4。适配器已默认强制 IPv4（`BAIDU_API_FORCE_IPV4=1`，绑定 IPv4 源地址）；实测 2026-09-25 该开关解决此问题。|
