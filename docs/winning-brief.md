# 获奖定位与证据策略

## 核心定位

面向街道与社区治理的生活圈服务缺口诊断和方案比较工具。不是“附近有什么”，而是“哪里确实缺、证据是什么、补一个点能改善多少”。结果只辅助调研，不代替正式规划审批。

老年友好社区是建议的演示切口，不是已经验证的客户市场。现阶段没有可公开引用的用户访谈、真实社区试点或推广收益，不在答辩中伪造这些证据。

## 评分对应

任务书：功能正确性与覆盖率 40%，API 深度与工程优化 30%，产品体验 15%，开源规范 15%。前两项共 70%，不能只优化答辩包装。

## 三个差异点假设

1. 直线可达与路网可达的差异由一条可复算路径说明，不只画一个复杂形状。
2. 不停留于缺口热图，允许新增一个候选设施并展示前后差异；候选增益和排序来自计算，不由模型拍数字。
3. 报告附数据来源、计算口径、未知点和证据编号。AI 只能引用事实，不能补造设施、用户反馈或效果。
4. 对企业题的直接响应不是“画一张热力图”，而是把真实 POI 检索、步行路线、1 公里专项检查和规划参考点串成一条可审计证据链。

必须调研已有百度地图、GIS、规划分析和开源项目，确认上述组合能解决什么现有流程痛点。当前不声称“首创”“行业领先”或“没有竞品”。

## 五分钟演示草案

- 0:00-0:30：一个经访谈确认的问题。尚未访谈时，不使用引号伪造用户原话。
- 0:30-1:20：先用离线样例演示直线范围、路网绕行、候选设施前后差异，保证断网时也能完整复现。
- 1:20-2:30：切到实时页，展示真实步行等时圈采样、设施路线证据和未知点处理。
- 2:30-3:30：展示 1 公里菜市场/药店/小学专项盲区，再点出按类别生成的规划参考点；强调它不是建设选址。
- 3:30-4:20：打开 Markdown/JSON 报告，追溯证据编号、查询画像、采样口径、API 请求量和警告。
- 4:20-5:00：说明真实验收、限流/回退/无 Key 安全边界，以及当前仍待人工核验、Docker 和第三方复现的事项。

实时页可以展示真实接口证据，但不能把一次地址检索包装成真实社区治理成效；没有访谈和实地试点，就不使用虚构用户原话、覆盖人数或落地收益。

## 答辩底线

不编造覆盖面积、节省成本、服务人数、置信度、政府合作、真实路线采样数。规划候选不等于建设选址。API 缺失不等于没有设施。讲故事的作用是组织证据，不能替代证据。
